### `ZDT TOUCH1.9.4`

该工程使用 STM32F103 和 ZDT EMM 风格命令，但主要电机传输是 CAN，不是当前 USART3 Modbus-RTU。已重点核对：

- `USER/cdpr_control.c`
- `USER/motor_smd.c`
- `USER/motor_can.c`
- `USER/motor_feedback.c`
- `USER/main.c` 中的四电机同步、反馈、电流保护和分段策略。

可借鉴内容：

- 四电机先入队、再广播同步。
- 每段完成后读反馈并校正软件累计位置。
- 用电流阈值识别过紧并在后续段降低速度、加速度和单段步长。
- 针对放绳上限增加子段数量。

不能直接移植内容：

- 0x6B 帧尾协议、CAN ID、固定四点脉冲表、`0..600` 坐标系和简单二维绳长公式。
- 该项目的电流阈值属于其电机、供电和机械结构，当前现场阈值为“待确认”。

已核对厂商 STM32F103 串口例程的 `Emm_V5.c/h`、`usart.c`、`main.c` 和接线说明。该例程使用 0x6B 帧尾的 EMM 协议，不是当前 X 固件的 Modbus CRC 帧，因此只能参考串口收帧和同步思路，不能据此解释当前 `CRC_BAD`。

厂商接线说明建议在主机端和总线最后一台电机端各加 `120 Ω` 终端匹配。现场是否已经安装、支线长度和电机串接顺序均为“待确认”。

Modbus Poll 工程文件本身可以读出版本化示例的地址：`10H(FD)位置模式控制.mbp` 使用功能码 `10H`、起始寄存器 `0x00FD`、5 个寄存器；`04H(36)读取电机实时位置角度.mbp` 使用 `04H`、寄存器 `0x0036`。当前现场工程的运动写入是 `0x00F0`，实时位置读取是 `0x0046`，这说明两边可能不是同一 X 固件/协议版本或存在地址别名。由于现场的多数命令已返回 `OK`，不能仅凭资料差异断言当前代码错误；应先逐台读取固件版本并用抓到的原始帧做一次寄存器映射验证。

PDF 协议正文尚未可靠抽取为文本，具体寄存器、异常码和时序参数仍应以现场驱动版本手册逐项核对。

### 主控板资料

已核对 `控制板资料\3，原理图\MiniSTM32 V4 IO引脚分配表.xlsx`：

- 核心 MCU 为 STM32F103RCT6。
- PB10/PB11 在开发板上连接 TFTLCD 的 D10/D11；未插 TFTLCD 时为完全独立 IO，可用于当前 USART3 TX/RX。
- PA2/PA3 在开发板上分别连 W25Q64 片选和 TF 卡片选；当前将其用于 USART2 时，相关外设占用/片选状态必须与现场硬件一致。
- PC0～PC3 在未插 TFTLCD 时可独立使用，符合当前手动 jog 使用条件。

MiniSTM32 V4 板本身的 IO 表没有确认板载 RS485 收发器。当前 USART3 后接的 RS485 模块型号、自动方向实现、供电和接线仍为“待确认”。
