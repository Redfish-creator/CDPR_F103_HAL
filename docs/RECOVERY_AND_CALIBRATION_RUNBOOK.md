# 总线恢复、绳长标定与逐段拟合执行方案

更新时间：2026-07-24

适用范围：当前四电机 STM32F103 CDPR。本文记录现场结论、固件保护逻辑和后续执行顺序；固件修改须以当前工作区实际版本和构建结果为准。

## 1. 两次停止必须分开处理

| 运行 | 停止点 | 已确认的直接原因 |
| --- | --- | --- |
| P1 | `CENTER-LT step=7/28` | MaixCAM 数据冻结；`cnt=856` 不增长，`age` 增至约 `27537 ms`，视觉精归零失败 |
| P2 | `LB-IN2 step=23/28 seg=3/3` | M3 缓冲写入依次返回 `REJECTED / CRC_BAD / CRC_BAD` |

P2 失败段：

```text
from=(-6.67,-6.67) -> (-8.00,-8.00)
dL=[-1.54,1.75,0.43,0.49] cm
cmd=[1.54,1.51,0.44,0.50] cm
bal=1
```

M1、M2 已缓存，M3 失败，M4 和同步触发均未继续。失败后 `soft=(-6.67,-6.67)`，因此不能记成已经到达 `(-8.00,-8.00)`。这次停止不能归因为几何路径。

## 2. M3 总线故障的最短排查路径

### 2.1 断电检查

1. 确认 A/B、信号地、屏蔽和电机电源接头没有松动。
2. 总线应尽量为菊花链，主机和物理末端各一个终端，不在每个支路重复加终端。
3. 若只有两个 `120 Ω` 终端，断电后 A-B 等效电阻通常接近 `60 Ω`；驱动内部网络可能影响读数，异常时继续按实际接线图核对。
4. 核对 M3 与其他三台的地址、`115200 8N1`、Modbus 模式、固件版本和参数。

### 2.2 空载与带载对照

1. 电机禁止运动时，分别对 M1～M4 连续读取位置、状态和固件版本，统计每台的 `OK/TIMEOUT/CRC_BAD/REJECTED`。
2. 再在低速、无明显过紧的中心附近重复。
3. 最后只在进入 RB/LB 负载区域时重复，记录 M3 供电电压、驱动状态和原始收发字节。

判断方式：

| 现象 | 优先方向 |
| --- | --- |
| 故障始终跟随 M3 驱动器 | M3 固件、参数、供电或驱动器本体 |
| 更换驱动器后故障仍留在原总线位置 | 线缆、支路、终端、共地或干扰 |
| 仅在绳张力增大时出现 | 电源压降、地弹、EMI、过流/保护状态 |
| 四台都随机出现 | 主控 RS485 收发器、自动方向时序或总线拓扑 |

厂商 `V1.0.7` 记录包含“修复概率通讯异常问题”。当前工程使用的 `0x00F0/0x0046` 与厂商 Modbus Poll 示例的 `0x00FD/0x0036` 也不一致，必须先按每台驱动的实际固件确认寄存器映射。

### 2.3 软件处理原则

- 读取命令可以重试。
- 相对位置缓冲写入收到 `CRC_BAD` 或超时后，驱动器可能已经接受命令，只是应答损坏；不能把无条件重发当作安全方案。
- `REJECTED` 必须记录原始 exception code，并在状态未查清前停止该组同步。
- 任一电机缓冲状态不确定时，四台均不广播触发；当前停止行为应保留。

## 3. RB 附近 M4 松紧问题

旧固件的 `bal=1` 启发式在半径达到 `8.0 cm` 后把主导放绳乘以 `0.86`。按本次日志打印精度对 RB 路径逐段重算：

当前固件已将该未经张力/电流验证的补偿停用（`MOTION_PATROL_BALANCE_ENABLE=0`），并将巡检基础速度设为 `300`（0.1 RPM）。下面的数值仅用于解释旧串口数据，不是当前下发参数：

| M4 指标 | 数值 |
| --- | ---: |
| 几何累计 `dL` | `24.299413 cm` |
| 累计下发 `cmd` | `21.856651 cm` |
| 两者差值 | `-2.442762 cm` |
| 编码器等效相对绳长 | `21.859202 cm` |
| 编码器对几何残差 | `-2.440212 cm` |

这说明 M4 的大部分几何/编码器差异来自现有平衡规则，而不是一个尚未证明的随机误差。它仍不能直接说明绳张力，因为编码器只测卷筒转角，松绳时不等于受力绳长。

当前已视觉确认的端点可作为后续标定种子：

| 目标 | 学习 soft | 编码器等效相对绳长 `[M1,M2,M3,M4]` |
| --- | --- | --- |
| LT | `(-19.47,14.27) cm` | `[4.059200,8.439103,20.190623,-18.218750] cm` |
| RB | `(20.01,-16.80) cm` | `[8.735984,6.334367,-19.612439,21.859202] cm` |

正值表示相对中心几何意义上的放绳，负值表示收绳。它们是编码器等效量，不是真实自由绳长，也不是张力。

注意：`soft` 是控制器命令空间坐标，不是物理平台坐标。比如 RB 的 `soft=(20.01,-16.80) cm`，而同一时刻视觉 `laser` 约为 `(19.80,-20.10) cm`。最终模型的输入应优先使用新鲜、目标圆匹配的 `laser` 坐标；`soft` 只作为命令历史和路径特征保存。

安全处理顺序：

1. 先复核 M4 的实际收放方向、出绳点、绕线层和有效半径。
2. 对每台卷筒分别在相同张力、相同绕线层下转固定圈数并测量实际出绳长度，不能四台共用一个未实测的 `5.25 mm`。
3. 在 RB 附近记录四台相电流或张力；如果 M4 松而其余三台紧，优先判断是否应该释放过紧组，而不是盲目继续收紧 M4。
4. 平衡增益只做单变量、低速对照，且必须同时看视觉位置、四台电流/张力和绳是否下垂；没有这些证据时不指定新的固定增益。

## 4. 稳定运行与高密度诊断样本

当前默认 `STABLE_LITE` 固件每个普通 segment 输出 `dL/cmd/通信结果/随后视觉`，但不再增加四次编码器轮询；日志明确写 `enc_sample=DEFERRED_TO_CORNER`。视觉确认角点时再由 `PATROL CAL/AVG` 保存四台真实 `enc`。若专门研究逐段绳长模型，可在静态通信通过后用高密度诊断构建恢复 `enc_before/enc_after/enc_delta`；读回不完整时仍必须保留 `NA` 和结果码，不能把 `cmd` 当成 `enc`。

稳定现场运行每个小段必须保存：

```text
run_id, timestamp, waypoint, step/total, seg/seg_total
soft_from, soft_to
dL[4], cmd[4], dir[4], mag[4], vmax[4], bal
enc_sample=DEFERRED_TO_CORNER
current[4], voltage/status/alarm[4]   # 寄存器映射确认后再增加
laser, circle, err, tilt, cnt, age, expected_circle
raw_tx, raw_rx, exception, crc_calc, transaction_ms  # 当前在失败事务打印
slack_label[4], trigger_result, sample_quality
```

角点完整训练样本的最低门槛：

- 四电机缓存和同步触发均成功。
- 视觉确认角点后，四台编码器全部读回成功。
- 视觉帧持续更新，`age <= 500 ms`。
- 看到的是本 waypoint 的目标圆；RT 当前看到 `(0,0)`，不能作为 RT 标定样本。
- 没有 `CRC_BAD/REJECTED`，没有松绳下垂或人工干预。

失败或陈旧样本仍保留用于故障统计，但不进入绳长拟合。

## 5. 任意平面点模型

先使用可解释的“几何基线 + 每电机残差”：

```text
L_i,cmd(x,y,h) =
    L_i,geometry(x,y)
  + r_i(x,y,approach_dir,cumulative_turns,winding_layer,history)
```

执行顺序：

1. 在已经验证安全的区域建立二维网格。
2. 同一个点从 `+x/-x/+y/-y` 不同方向到达并重复采样，区分位置误差与方向滞回。
3. 每个电机独立拟合双线性网格、分片线性或 RBF 残差。
4. 留出未参加拟合的网格点验证，分别报告视觉误差、编码器重复性和松紧状态。
5. 数据量足够后再比较小型神经网络；训练在电脑端进行，STM32F103 端优先部署查表和低阶插值。

对当前机械，第一版更建议同时拟合两个输出：

- 位置控制表：`(laser_x, laser_y, approach_dir, history) -> enc_target[4]`。它直接回答“到这个平面点四台电机应处于什么相对位置”。
- 物理绳长表：`(x,y,...) -> L_actual[4]`。只有在每台卷筒有效半径和绕线层测量可靠后，才把编码器目标换算成真实绳长。

这样不会把“视觉命中但绳子松弛”的状态误认为已经得到真实绳长；张力/松紧应作为独立标签或约束。

当前 LT `n=2`、RB `n=1`、RT/LB `n=0`。新固件已经尝试在每个普通段和
细调段读取四电机编码器，并可用 `tools/fit_rope_model.py` 离线拟合；但尚无
新格式的完整现场运行日志，因此现在仍只能得到局部诊断，不能声称已经获得
全平面准确模型。

## 6. 完成判据

1. 空载和带载通信测试均不再出现不可解释的 M3 `CRC_BAD/REJECTED`。
2. 视觉 `cnt` 连续增长，巡检期间 `age <= 500 ms`；错误圆不计为命中。
3. 每个 segment 都有四台运动前后编码器、通信结果和有效视觉。
4. 模型在独立验证点达到约定的位置误差，并且四根绳无下垂、无持续过紧。
5. 只有满足以上条件后，才把新的残差表或平衡参数写入固件。
