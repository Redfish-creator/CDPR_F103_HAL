# DECISIONS

本文记录本次会话中已经确认、已经否决和仍待确认的工程判断。

## 已确认方案

| 决策 | 结论 | 理由和来源 |
| --- | --- | --- |
| 坐标系 | 使用中心为原点，`+x` 右，`+y` 上，单位 cm | 串口、代码和现场描述一致 |
| 四电机位置 | M1 左下，M2 右上，M3 右下，M4 左上 | 当前运动模型和用户对“电机3角点/电机4对角”描述一致 |
| 中心归零 | KEY0 视觉归零后保存电机零点 | 用户工作流和当前串口已验证 |
| 回零策略 | 编码器回零后仍需要视觉精归零 | 编码器为零时激光仍可能偏离中心 |
| 巡检策略 | 四角之间回中心刷新视觉零点 | 可以降低累计误差，已经在流程中运行 |
| 角点命中 | 角点必须以视觉圆心确认，不应只按编码器目标算命中 | RT 曾只到编码器目标但视觉未确认 |
| 比赛日志 | 默认使用精简日志；已有逐段证据保留，`PATROL SEG/NODE/CAL/AVG` 与周期视觉只在专项诊断构建恢复 | 用户确认电机数据已经读取很多，当前最重要的是正常、高效、准确完成题目；USART1 阻塞输出也会占用 CPU 时间 |
| 通信失败处理 | 连续 buffer 失败时停止全部电机并中止 | 最近 LB-IN2 的 M3 CRC_BAD 证明必须防止部分电机动作 |
| 不确定缓冲应答 | 相对缓冲写入仅在发送前 `UART_BUSY` 时重试；`TX_FAIL/TIMEOUT/CRC_BAD/REJECTED/FRAME_BAD` 不重发 | 请求可能部分发出或驱动已经接收，重发会造成未知缓存状态 |
| 上层运动失败 | 普通巡检段/细调段通信失败后先停四电机、等待 `800 ms`、电机回零、视觉归零，再从当前角点 job 的 `IN1` 最多重走 `3` 次；原地不重发同一条相对缓冲命令 | 底层失败后缓冲状态未知，不能直接重发；先回中心重建编码器零点和视觉中心，再从已知状态重启当前角点任务 |
| 手动点动通信失败 | 点动分组或停止出现非 `OK` 后锁止 PC0-PC3，必须按 KEY0 完成编码器返回和视觉重归零后再解锁 | P3 中 M2 多次 `TIMEOUT` 且 `rx_len=0`，此时软件积分坐标与真实电机位置可能失配 |
| 巡检通信失败后的操作 | `KEY0` 回零并解锁手动点动；`PA0` 重新自动回中心后再尝试巡检；不提供绕过回零的继续键 | 相对缓冲状态不确定时直接续发会重复或丢失绳长 |
| USART3 收帧 | 默认使用发送前预开的 USART3_RX DMA 扫帧；旧逐字节阻塞接收只保留为编译期 A/B 开关，不作为现场默认 | 2026-07-26 阻塞对照在 M1 `0x03` 收到 `9/11` 字节并记录 `uart_error=0x00000008`，明确证明 STM32F1 发生 ORE 丢字节；读命令和 `0x10` 继续发送前预开 DMA，`0x06` 因本机回显与正常应答相同而仍在发送后接收 |
| 巡检总线节奏 | 默认每个 segment 只做四台缓冲写入和一次广播触发，停稳 `300 ms` 后用异步 USART2 视觉更新下一段；不做逐段、角点标定或回零后遥测读取。每个角点回中心前仅保留四台当前位置读取 | 自动视觉回零与巡检使用同一组 `4×0x10 + 1×0x06`。普通 segment 从旧约 `9` 个请求降为 `5` 个；正常四角位置读取由旧约 `48` 次降为约 `16` 次，保留的读数直接参与安全回零 |
| V11 M2 写入静默 | 手动点动写间隔改为 `120 ms`，巡检写间隔改为 `160 ms`；M2 每次 `0x10` 缓冲写前额外静默 `120 ms`、成功后额外静默 `80 ms` | V10 手动点动在 DOWN 起步时 M2 `rx_len=0`、`402 ms` 超时；巡检在 `RT-APP step=10/28 seg=2/5` M2 `rx_len=0`、`401 ms` 超时。M2 在完整应答窗口内完全未回包，待确认是否为驱动/RS485/供电/线缆问题 |
| V12 中心重置恢复 | `nohome` 视觉归零写间隔改为 `160 ms`；中心重置归零失败后最多做 `3` 次“停机等待 `800 ms` -> 电机回零 -> 视觉归零”恢复 | V11 已连续通过 `LT`、`RT` 和 `CENTER-RT` 前的巡检段，停止在 `CENTER-RT` 后视觉归零的 M2 `0x10` 写入 `rx_len=0`、`402 ms`。原 `nohome` 基础间隔仍为 `20 ms`，比巡检路径短；失败后不能重发同一条相对缓冲命令 |
| V13 角点张力 profile | 已回退，不作为当前代码 | V12 之后的 V13 现场试验引入角点 profile，但后续 V15 变差；用户已要求回到 V12 |
| V12-Q3-ORDER-PC2OK-RETRY3 选择顺序和恢复次数 | 当前试用 | KEY1/PA15 作为 Q3/OLED 顺序选择模式键；进入选择模式后 PC0 上一个、PC1 下一个、PC2 确认步骤、PC3 返回修改，OLED 排列完整已选顺序，选满四角后 PA0/WK_UP 按该顺序巡检。USART1 默认只打印最终顺序或故障。巡检运动失败和中心重置恢复上限均为 `3` 次，仍不原地重发不确定相对命令 |

## 已否决或不再单独依赖的方案

| 方案 | 否决原因 |
| --- | --- |
| 只靠理论几何绳长走四角 | 现场绳松弛、摩擦、绕线层、相机误差导致软坐标和激光落点不一致 |
| 只靠电机编码器回零 | 电机回到零不代表吊舱视觉回中心 |
| 中心附近盲目按大编码器差回零 | 可能因软坐标/编码器状态不一致导致大动作，当前已有保护策略 |
| 只在四个圆心采样 | 用户明确要求每一步都采，任何平面点都要能拟合绳长 |
| 看到角点绳松就简单整体加张力 | 已有过局部过紧风险；会增加结构损坏和电机对抗风险 |
| RT 仅按编码器目标认为成功 | 串口显示 RT 识别到的是 `(0,0)` 圆，视觉未确认 |
| 连续 CRC_BAD 后继续巡检 | 会带来四电机命令不同步风险，必须停机 |

## 当前张力/通信安全配置（2026-07-26）

旧配置中的巡检平衡启发式曾使用：

- `MOTION_PATROL_BALANCE_RADIUS_CM = 8.0 cm`
- `MOTION_PATROL_DOM_PAYOUT_RATIO = 0.70`
- `MOTION_PATROL_DOM_PAYOUT_GAIN = 0.86`
- `MOTION_PATROL_SIDE_PAYOUT_GAIN = 1.03`

按 RB 日志重算，这组规则会让主导放绳少发约 `2.442762 cm`，而现场随后出现断绳，因此已从现场巡检路径停用。当前安全配置为：

- `MOTION_PATROL_BALANCE_ENABLE = 0U`，巡检不再应用未经张力/电流验证的放绳补偿。
- 巡检基础速度 `MOTION_PATROL_BASE_VMAX = 300`（0.1 RPM），已从 FIT360 试验的 `360` 回退。
- FIT360 经验目标 seed 已禁用：`EDGE_PATROL_USE_TARGET_SEED = 0U`。历史 seed LT `(-17.30,14.90)`、RT `(19.10,18.30)`、RB `(17.70,-16.47)`、LB `(-15.42,-13.82)` 只保留作后续分析；当前只使用 V12 nominal soft target，除非本次运行中同一角点已由视觉确认并在 RAM 内学习。
- 巡检路径采用很小的松绳试验偏置：收绳 `0.99`、放绳 `1.01`；巡检平衡启发式仍关闭。
- 角点1按现场电机编号定义为 M1 所在的 LB 角。当前只对 LB 角点任务使用专用张紧偏置：收线 `1.02`、放线 `0.99`；LT/RT/RB 继续使用基础收线 `0.99`、放线 `1.01`。
- 巡检路径已拆为四个独立角点任务；旧 `OUT1/OUT2/CENTER-*` waypoint 不再作为角点之间的回程路径执行。每个角点后调用电机回零、视觉中心归零、重新发送 `&mode,total#` 并重置 segment encoder baseline。
- 当前已回到 V12，不启用 V13 per-corner sign-dependent profile。
- 手动点动恢复为中性收/放绳增益 `1.00/1.00`，因为 P4 的 `0.99/1.01` 让起始点动姿态显示偏松。
- 手动点动每个电机缓冲写入基础间隔为 `120 ms`；P3/P10 的 M2 超时根因仍待确认，这只是降低连续事务压力，不代表已修好现场总线。
- 巡检默认四台缓冲写入基础间隔 `160 ms`，每个 segment 停稳 `300 ms`，
  不再逐段、角点确认或回零完成后轮询编码器；每个角点回中心前只读取四台
  当前位置以计算安全返回量。需要专项诊断时由 `Debug-dense` 恢复高密度读回。
- 默认 `APP_COMPACT_LOG=1`、`MOTION_COMPACT_LOG=1`，周期视觉、
  `PATROL SEG/NODE/CAL/AVG` 和正常事务明细均关闭；状态转换与所有失败诊断保留。
  广播同步触发本身没有应答，精简日志不能解释为逐段编码器验证。
- 巡检缓冲写顺序改为 `M2 -> M1 -> M3 -> M4`。M2 在上一个 segment 的 `300 ms` 停稳窗口和自身额外 `120 ms` 静默后首先通信；四台仍全部缓存成功后才使用同一广播触发，因此没有改变电机编号、命令量或同步动作语义。
- DMA 扫帧看到噪声或可能的本机回显后仍保留完整 `400 ms` 应答窗口，不再
  因任意前缀停止增长 `20 ms` 就提前结束真实从站应答等待。
- 视觉归零/nohome 小步运动的四台缓冲写入基础间隔为 `160 ms`；这是针对 V11 在 `CENTER-RT` 后视觉中心重置阶段 M2 完全无应答的修正，不改变绳长命令量。
- M2 每次 `0x10` 缓冲写前额外静默 `120 ms`，成功后额外静默 `80 ms`；这是针对 V10 两次 M2 `rx_len=0` 超时的现场试验，不改变绳长命令量。
- 上层手动回零/预紧的 M2 缓冲写入也加同样 `120 ms` 前静默和 `80 ms` 后静默，避免自动恢复时重新落回较短 M2 事务间隔。
- 当前已回到 V12 串行通信节奏，不启用 `V12-M1M3-POLL-TIM2` 的 TIM2 轮询调度或写前状态轮询。
- 巡检普通段/细调段运动通信失败后启用 job 级受限恢复：停止四电机、等待 `800 ms`、电机回零、视觉归零，再从当前角点 job 的 `IN1` 最多重走 `3` 次；第 `4` 次同类失败仍中止。
- KEY1/PA15 为 Q3/OLED 角点顺序选择模式键；选择模式内 PC0 上一个，PC1 下一个，PC2 确认当前步骤，PC3 返回修改。退出选择模式后 PC0-PC3 恢复手动点动。
- V15 临时松线参数已经从当前代码删除，仅作为失败实验记录保存在文档和
  `data/patrol_evidence_2026-07-25-v15-run10.csv`。
- 中心轻预紧保持 `40` counts、`vmax=60`、稳定 `300 ms`；这是现场认为合适的回零参数，不因本次巡检问题改变。

这不是最终真实绳长或张力模型。重新启用任何平衡补偿前，必须有低速重复数据以及可确认的电流/张力证据；当前是否有可靠张力或电流代理量仍为“待确认”。

## 参考工程迁移边界

只读检查了 `D:\IPCS班级项目\control_four - 副本` 和
`D:\IPCS班级项目\ZDT TOUCH1.9.4`。两者可迁移的原则是：

- 中心只做小幅、固定的预紧，再停稳和重新确认中心；不能靠持续整体收绳维持张力。
- 运动拆成小段，并限制速度/加速度；收绳和放绳使用不同增益时必须有现场证据。
- 发现电流过大、状态异常或通信失败时，先减速/缓解或停止，不继续同步触发。
- `ZDT TOUCH1.9.4` 中的 `40` 脉冲、约 `300 ms` 稳定等待与当前中心参数方向一致，因此保留。

参考工程的电流阈值、寄存器和速度单位属于不同电机/机械，当前项目是否兼容为“待确认”，没有直接复制到本工程。

历史保留的逐电机放绳比例接口
`MOTION_PATROL_M1_PAYOUT_SCALE ... MOTION_PATROL_M4_PAYOUT_SCALE` 默认仍为
`1.00`，且只有旧 `MOTION_PATROL_BALANCE_ENABLE` 打开时才会参与旧平衡启发式。
当前 V12 不使用 V13 runtime profile。

本次 RB 路径离线重算发现：`bal=1` 的主导放绳增益 `0.86` 使 M4 的累计 `cmd` 约为 `21.856651 cm`，而几何累计 `dL` 约为 `24.299413 cm`，差约 `2.442762 cm`，与 M4 编码器等效残差 `-2.440212 cm` 基本重合。该结果只说明软件平衡规则是首要待验证因素，不等同于已经测得张力，也不授权直接修改增益。

## 待确认问题

- M3 在 LB-IN2 报 REJECTED/CRC_BAD 的根因。
- M2 在 P3 手动点动中多次 `TIMEOUT`、`rx_len=0`、耗时 `253–254 ms` 的根因。
- V8 巡检在相同 `LT-IN1 seg=3/3` 两次分别由 M4/M2 完全无应答的根因；V9 总线节奏能否消除该现象待现场验证。
- MaixCAM 长时间卡住计数的根因。
- RT 为何未识别到右上圆，而持续看到 `(0,0)`。
- RB/M3 角点 M4 松弛是由几何模型、卷线半径、滑轮摩擦、线长初始偏差还是电机保持造成。
- 是否存在实际张力传感器、弹簧预紧、配重或机械导线器。
- 现场实际滑轮出绳点、吊舱孔位和相机外参。
- 是否需要把标定数据写入 Flash、外部 EEPROM、SD 卡或只通过 PC 串口保存。
