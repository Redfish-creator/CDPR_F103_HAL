# 串口逐段采集与实际绳长模型

更新时间：2026-07-26

## 当前结论边界

- `data/serial_evidence_2026-07-24.csv` 是从本次聊天粘贴的串口输出中逐项核对出的证据表，不是原始串口文本的完整替代品。
- 已保存的历史/诊断输出在每个运动小段包含 `from/to`、`dL[4]`、`cmd[4]`、
  `bal`、四电机缓冲结果、同步触发结果和随后取得的视觉数据。
- 当前默认 `DMA-COMPACT1` 比赛固件不打印 `PATROL SEG/NODE/CAL/AVG`，也不在
  segment、视觉确认角点或回零完成后执行遥测编码器读取。每个角点回中心前的
  四台位置读取仍保留，因为它们直接计算返回电机零点的位移。
- 只有专门的 `Debug-dense` 诊断构建才恢复逐段
  `enc_before/enc_after/denc`、角点 `PATROL CAL/AVG enc` 和完整过程日志。
- 现有视觉数据是运动后取得的最新帧，但必须同时保留 `cnt` 和 `age`。帧计数不增长且 `age` 递增时，坐标是陈旧值，不能用于拟合。
- `soft` 是控制器内部目标/估计，不是视觉实测位置；`laser` 是激光点视觉坐标；`circle` 是当前检测到的圆心；`err=laser-circle`；`enc` 是相对电机零点的 0.1° 单位位置。编码器零点不等于视觉中心归零。

## 诊断构建输出格式

`Debug-dense` 的每个 segment 会输出三行、共享 `seq`；默认比赛固件不输出
这些行：

```text
PATROL SEG ... release<=... from=... to=... dL=[...] cmd=[...] gain=[...]
PATROL SEG BUS ... dir=[...] mag=[...] vmax=[...] motor=[...] trigger=... trigger_attempted=...
PATROL SEG DATA ... tick=... enc_sample=DEFERRED_TO_CORNER
    laser=(x,y,age,cnt=...) circle=(x,y,age,cnt=...) err=(...)
    tilt=(x,y,age,cnt=...)
    quality=CMD_OK_VISION_FRESH_ENC_DEFERRED|GOOD|ENC_PARTIAL|VISION_STALE|CIRCLE_STALE|COMM_FAIL
```

`PATROL SEG BASE enc=DEFERRED profile=CORNER_ONLY` 和
`CMD_OK_VISION_FRESH_ENC_DEFERRED` 是上一版稳定日志字段；它们只表示该段没有
编码器读回，不能解释为实际位移已验证。`seq` 是固件单调递增的运动事务号；
`step/seg` 是路径位置，`fine=1` 表示角点精修。通信异常的原始 `tx/rx`、
长度、CRC、exception code、耗时和 `uart_error` 在精简比赛固件中仍保留。

## 专项诊断的下一批原始记录格式

只有用户明确要求重新做通信或绳长模型实验时，才使用 `Debug-dense`：建议每次
上电生成唯一 `run_id`，每个 segment 在“发命令前”和“运动完成后”各落一条
记录，原始文本与结构化 CSV 同时保存。比赛默认不承担此采集负载。

每段至少记录：

1. 运行上下文：`run_id`、单调时间、巡检模式、waypoint 名称、`step/total`、`seg/seg_total`。
2. 运动目标：`from_soft`、`to_soft`、理论 `dL[4]`、实际下发方向、`cmd[4]`、速度、加速度、`gain(T/P)`、`bal` 及限幅原因。
3. 通信证据：每台电机每次 attempt 的结果、请求字节、原始响应字节、响应长度、CRC 接收值/计算值、Modbus exception code、同步触发结果、事务耗时。成功帧可只保留摘要，失败帧必须保留原始十六进制。
4. 编码器读回：只有专项诊断才启用角点或每段
   `enc_before[4]`、`enc_after[4]`、`enc_delta[4]`。同时在每次实验开始记录
   每台驱动的固件版本、协议/地址映射、相电流、母线电压和温度（若寄存器支持）。
5. 视觉证据：`laser/circle/err/tilt`、各自 `cnt`、`age`、激光与圆是否配对、圆的类别、是否为本 waypoint 的目标圆。
6. 现场标签：M1～M4 的松/正常/紧、是否下垂、是否打滑、异常声音、人工急停等。无法确认时写“待确认”。

一条运动不能仅以“命令已发送”作为拟合证据。完整角点拟合样本应以“同步触发
成功 + 诊断编码器读回有效 + 视觉有效”为准；比赛默认的状态日志不具备逐段
真实编码器标签。只有部分字段有效的记录保留，但单独标记质量等级。

## 模型路线

目前不适合直接训练黑盒深度网络。历史样本虽然已覆盖四角，但重复次数、现场
松紧标签和跨方向样本仍不足。样本规模和可观测量不足，黑盒模型会把松线、
路径方向和通信异常混在一起。

推荐使用“几何基线 + 每电机残差模型”：

```text
L_i,actual(x,y,h) =
    L_i,geometry(x,y; anchor_i, platform_attach_i, dz)
  + r_i(x,y,approach_dir,cumulative_turns,history)
```

其中：

- `L_i,geometry` 只负责可解释的几何主趋势。
- `r_i` 学习实际安装偏差、有效卷径变化、摩擦、绕线层和方向滞回。
- `h` 表示路径历史；同一 `(x,y)` 要分别采集从不同方向进入和离开的样本。
- 编码器只能测卷筒转角，不能直接测绳张力或真实自由绳长。松线时即使编码器到位，实际绳长仍可能不受约束。

第一阶段可在电脑端使用每电机独立的二维分片线性、双线性网格、薄板样条或 RBF 残差表。数据充分后再比较小型神经网络。STM32F103 端优先部署查表与低阶插值参数，训练放在电脑端完成。

## 当前两点的离线残差试算

`data/calibration_residuals_2026-07-24.csv` 用学习到的 `soft`（不是视觉
`laser`）和当前代码的几何常量（锚点 ±30.0 cm、`dz=18.75 cm`、平台挂点
偏移 `4.25/3.25 cm`、`1091.348181202 0.1deg/cm`）做了一个只读试算：

- LT 的 M3 残差约 `-2.081305 cm`。
- RB 的 M4 残差约 `-2.440212 cm`，四台中绝对值最大。

还有一个比“卷筒半径”更直接的现象：按本次旧固件日志中从中心到 RB 的逐段坐标，重新执行旧巡检平衡规则（半径达到 `8.0 cm` 后，主导放绳增益 `0.86`，次要放绳增益 `1.03`），M4 的几何累计放绳约为 `24.299413 cm`，实际下发 `cmd` 累计约为 `21.856651 cm`，少了 `2.442762 cm`。这个差值与 M4 编码器等效绳长 `21.859202 cm` 对几何值的残差 `-2.440212 cm` 几乎相同。该结果支持当前版本停用 `bal` 补偿；它是否在现场表现为松绳，还要用低速重复实验、驱动电流/状态或张力测量确认，不能仅凭残差判断力的方向。

因此，M4 的卷筒有效半径、绕线层、出绳点和方向符号仍需复核，但应先验证/重新标定 `bal` 规则，再考虑机械补偿；不要先盲目改变整个平台张力。这个结论只针对本次 RB 路径，不能外推到全平面。

如果暂时强行把几何增量等同于编码器增量，RB 样本的 M4 会得到约 `5.836074 mm` 的等效半径，LT 样本的 M3 约 `5.791184 mm`，都高于代码中的 `5.25 mm`。这只能作为“绕线层/有效半径可能变化”的诊断线索；它也可能包含安装尺寸误差、绳端滑移或视觉/编码器零点偏差。

## 采样与验证

- 在安全范围内采用密集网格，而不是只采中心和四个圆心。
- 每个网格点至少做正向、反向和重复到达，区分系统误差与滞回。
- 先稳定视觉和 RS485；通信失败样本不进入绳长拟合。
- 训练集与验证点分开，最终按视觉位置误差、编码器重复性和松紧标签分别报告。
- 在没有张力传感器或可靠电流代理量前，不宣称已经得到“最合适张力”，也不通过四电机统一多收线来掩盖松线。

## 电脑端拟合工具

保存一份完整串口文本后运行：

```text
python tools/fit_rope_model.py --log run.txt --out data/rope_model.json --header data/rope_model_generated.h --predict 0 0
```

工具默认只使用 `status=OK`、`complete=1`、四编码器有效、视觉 `age<=500 ms` 且 `quality=GOOD` 的样本；其余样本只计入 rejected 数，不进入拟合。输出是“几何绳长 + 平面残差”的编码器等效目标，不是未经卷筒实测的自由绳长或张力模型。

## 当前待确认项

- 现场 RS485 转换器型号、是否自动方向、DE/RE 时序、总线拓扑、终端电阻、偏置电阻、屏蔽与共地方式。
- M3 的 `REJECTED` 对应的原始 Modbus exception code。
- `CRC_BAD` 时收到的原始字节和长度，是否混入上一事务残留帧。
- 四台驱动的 X 固件版本是否一致；厂商记录中的 `V1.0.7` 有“修复概率通讯异常问题”的变更。
- 当前工程使用的运动寄存器 `0x00F0`/位置读取 `0x0046` 与厂商 Modbus Poll 示例 `0x00FD`/`0x0036` 的版本映射关系。
- 四台驱动的供电压降、报警状态、固件/协议配置是否完全一致。
- 每台卷筒的实际有效半径、绕线层数、出绳点和平台连接点。
- RB 附近 M4 的松弛程度及可重复性；目前只有人工现象描述，没有张力/电流测量。
